## 2. 场景描述（来自 `snapshots/cam_video2.jpg` 实拍）

**环境类型：室内办公室 / 机器人实验室，不是干净的实验台。**

```
                        ┌──── 天花板：矿棉板吊顶 ────┐
                        │  大量嵌入式面板灯 + 筒灯   │  ← 多光源、顶光、强反光
                        └────────────────────────────┘
   [另一台机器人]              [本体 astrabot]           [白板/挂纸架]
   粉/肉色包裹的臂              白色双臂人形               [办公工位×N]
   放在浅蓝桌布的桌上           深色面罩头部               显示器、椅子、人
   旁边有黑色显示器/箱          双臂**向两侧平举**         地上堆纸箱
        │                            │                        │
   ─────┴────────────────────────────┴────────────────────────┴─────
        [绿白格纹桌布的桌子] —— 桌面上有一个 **白色/浅粉碗，碗里有红色物体**
        [白色曲边桌（前景，离相机最近）] —— 桌面**空**
   ─────────────────────────────────────────────────────────────────
        地面：灰色条纹地毯 · 桌下与桌旁散放多个**瓦楞纸箱**
```

### 2.1 场景里有什么（清单）

| 类别 | 具体内容 | 对"放积木"任务的影响 |
|---|---|---|
| **工作台面** | 至少 2 张桌：① 白色曲边桌（前景，台面空）② 绿白格纹桌布的桌子 | ① 白色台面 → 与浅色积木对比度低；② 格纹桌布 → **强纹理会干扰分割/背景建模** |
| **台面现有物体** | 绿桌布上一个**白/浅粉碗，内含红色物体**；白桌台面空 | 属于杂物，需在实验前清场，否则算入碰撞体 |
| **🔴 积木** | **画面里看不到任何积木** | **场景尚未布置任务物体 —— 这是开工前必须先做的事** |
| 光照 | 吊顶大量面板灯+筒灯，多光源顶照 | 强反光、多重阴影、镜面高光；纯 RGB 抓取姿态估计会不稳，**更需要 ZED 的深度** |
| 相邻机器人 | 左侧另一台机器人（粉/肉色臂套） | 若同时上电，是动态障碍物；同网段还可能 DDS 串扰（`ROS_DOMAIN_ID=12` 需与其错开确认） |
| 人 | 右侧工位有人在坐 | **安全约束**：自主运动必须有急停 + `collision_monitor` |
| 地面障碍 | 桌下 / 桌旁多个瓦楞纸箱 | 底盘若要移动，Nav2 costmap 里是障碍；本阶段建议**底盘锁死不动** |
| 地面 | 灰色条纹地毯 | 地毯 → 底盘定位漂移比硬地面大；也意味着**机器人站位不是刚性固定的** |

### 2.3 激光雷达（`/scan` 实测参数）

```
frame_id:        lidar_link
angle_min/max:   -1.5708 … +1.5708 rad   → 前向 180° FOV
angle_increment: 0.002618 rad            → 0.15°/点，约 1200 点
range_min/max:   0.01 … 50.0 m
scan_time:       0.0659 s                → ≈ 15 Hz
```

→ 雷达装在底盘（`lidar_link`），**扫的是地面层平面，看不到桌面上的积木**。
它的作用是底盘安全，不是任务感知。

## 5. 场景侧结论

- 🟢 场景是**真实可用的办公桌面环境**，有桌、有台面、有充足光照，物理上适合做桌面 pick & place 练习。
- 🔴 但场景**尚未为任务布置**：没有积木、台面有杂物、没有栅格垫、没有纯色背景。
- 🟢 **腕部两路相机已修复（B7 解决，镜头盖问题）** → 4 路图像通道里已有 3 路物理可用（左腕/右腕/胸部）。
- 🔴 剩余感知阻塞：**头部 ZED 死（B1）** + **EE 位姿不发（B6）**。
  ZED 是唯一的深度/立体源，也是 `observation_images_head` 通道；不修就没有可靠的 3D 抓取位姿。
- 结论：**场景条件"可补齐"，感知条件还差 ZED 这一环。** 修 ZED（本 workspace 的名字来源）是解锁 S1 的关键前置。

> ### ⚠️ 上面这三条已被推翻（2026-08-11）
>
> - **ZED 从来没死**，它一直在 ROS 图上发（domain 12）。"修 ZED"这个前提消失了 ——
>   本 workspace 的名字来自一个不存在的故障。
> - **B6（`/ee/pose` 不发）不是阻塞**：FK 绕法已用真机 `/tf` 验证到 **0.5 mm**，
>   积木在爪子里时 FK 就是积木位置。
> - 场景侧现在也基本齐了（积木已布置、换成白桌面、桌高已卷尺量过）。
>
> **所以卡点不在场景、不在相机、也不在运动学。** 38 次成形试验 `grasped` **0**，
> 而失败原因每次都不同；缺的是**一次可信的手眼标定**（§4 最后一行），
> 以及一条能稳定走到探测点的路径（`docs/10` §4.1）。详见 [`STATUS.md`](../STATUS.md)。
