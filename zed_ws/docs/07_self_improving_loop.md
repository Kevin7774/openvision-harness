## 0. TL;DR

**循环 = 提出实验 → 执行 → 判定 → 决定下一个试什么。**
在这台机器上，卡住循环的不是算法，是**重置**：

```
              ┌───────────────────────────────────────────┐
              │                                           │
              ▼                                           │
   ┌──────────────────┐   judge   ┌──────────┐   判定通过  │
   │ 正向 episode      │──────────▶│  落盘     │───────────┤
   │ 散乱 → 收成一排    │           │ LeRobot   │           │
   └──────────────────┘           └──────────┘           │
              ▲                                           │
              │                    ┌──────────────────┐   │
              └────────────────────│ 逆向 episode      │◀──┘
                    重置完成         │ 一排 → 散乱       │
                                   │ = 重置 = 数据      │
                                   │ = 域随机化器       │
                                   └──────────────────┘
                                            │
                                    找不到全部 N 块
                                            ▼
                                     🛑 停机呼人（记 unrecoverable）
```

**三条设计决定：**

1. **重置不是运维步骤，是循环里的一条 episode。** 选 `04` 的 **C6**（散乱↔收成一排）
   而不是 C7（堆塔），因为 C6 的逆过程本身是合法 pick&place，C7 的逆过程（塔倒了）要人扶。
2. **散开必须实现成「把每块放到一个随机采样的目标位姿」**，不是「推乱」。
   这让它可判定、可训练，而且**目标位姿是自己下的命令 → 自带真值标签**。
3. **物理措施优先于算法措施。** 全机没有任何接触反馈（`effort` 全 `.nan`），
   机器人**察觉不到自己把积木推下了桌**。所以边界必须是几何的：**一道挡边**。

## 2. 循环的状态机

| 状态 | 做什么 | 判定 | 失败去哪 |
|---|---|---|---|
| `S_HOME` | 臂回 home，爪全开（`close01=0.0`），头钉在 `head_pitch=+40°` | 14 路关节到位 | 超时 → `S_HALT` |
| `S_OBSERVE` | 固定检查位姿下取 ZED 一帧 → 桌面平面 + N 块位置 | 找到 **全部 N** 块且都在工作区内 | 缺块 → `S_HALT` |
| `S_FORWARD` | 执行「收成一排」 | ZED 场景级：N 块共线、间距在容差内 | 记 fail，仍进 `S_OBSERVE` |
| `S_LOG` | 按 LeRobot schema 落盘（含 judge 的 verdict 和**弃权标记**） | — | — |
| `S_RESET` | 执行「散开」：逐块放到采样出的目标位姿 | ZED：每块落在目标 r 内 | 记 fail，仍进 `S_OBSERVE` |
| `S_HALT` | 停机、呼人、记 `unrecoverable` 事件 | — | — |

**三条不许违反的规则：**

- **`S_RESET` 也落盘。** 它是一条正常 episode，只是任务目标不同。不落盘等于扔掉一半数据。
- **`S_FORWARD` 失败不触发特殊处理**，直接进 `S_OBSERVE`。失败态就是下一条的初始态，
  这正是选逆过程任务换来的性质 —— **循环不需要「恢复」，只需要「继续」**。
- **`S_HALT` 绝不重试。** 找不到块就停。反复重试会把一次可恢复的偏差
  磨成一次真正的不可恢复事件，而且会在日志里伪装成正常运行。

## 3. 重置子系统：散开采样器

这是唯一需要新写的核心逻辑。它同时是三样东西：**重置器 + 域随机化器 + 课程表**。

### 3.1 目标位姿采样

```
sample_scatter_targets(N, table_plane, workspace_polygon, difficulty) -> [(x, y)] × N
```

约束（全部是硬约束，不是偏好）：

| 约束 | 值 | 为什么 |
|---|---|---|
| 目标必须在**可达带**内 | 挪完底盘后重测；旧数 `x∈[0.22,0.46]` | 否则下一条正向 episode 直接注定失败 |
| 且**内缩留余量** | 边界内缩 ≥ 5 cm | 一次失败把块推偏 5 cm，它应该**仍然可抓** |
| 块间最小间距 | ≥ 爪宽 + 余量 | 无接触反馈，挨太近抓 A 会撞 B 且察觉不到 |
| 目标必须在 ZED **视野**内 | 用固定检查位姿的投影校验 | 看不见 = 判不了 = 这条 episode 白跑 |
| 姿态 | **不采样** | 用对称立方积木 → 姿态无关，问题规模减半（§4） |

### 3.2 `difficulty` 就是课程表旋钮

**风险：分布塌缩。** 如果散开总是把块放到正向策略**已经会处理**的位姿上，
循环就停止探索了 —— 曲线很漂亮，能力不涨。

所以难度调节做在**散开方向**，不做在正向任务上：

| difficulty | 采样分布 |
|---|---|
| 低 | 可达带中心区、块间距大 |
| 中 | 全工作区均匀 |
| 高 | 偏向可达边界、块贴块、贴挡边 |

**建议：按正向成功率自适应提难度，但保留一个固定比例（如 20%）的均匀采样**，
用来持续测量「无偏成功率」。否则难度和成功率互相追逐，你会失去唯一的进度标尺。

### 3.3 自带标签

散开方向的目标位姿**是自己下的命令**，真值按构造已知。
→ 一条**持续的、带真值的数据流**，正好喂 `09` §1.4 要求的 golden set 和 judge 标定。

**这是选 C6 而不是 C7 的第二个理由，而且比第一个更重要**：
它顺手解决了「judge 拿什么校准」这个在自进化里最难的问题。

## 6. 验收门槛：MTBH ≥ 8 h

**MTBH = 平均人工干预间隔时间。** 这是决定「研究 demo 还是数据引擎」的那一个数。
反解出的要求（推导见 `09` §4）：

> 8 h 无人 ≈ 1 920 条 episode → **不可恢复率 < 0.052 %/episode**
> 按 30% 成功率折算 = **1350 次失败里最多 1 次不可恢复**

**顺序不能反 —— 先物理，后算法：**

1. 完成 §4 的 P1–P6（**P1 挪底盘是第一步**，见 §5 的红字）
2. 重测桌高 + 可达带，重跑 `05` §E0 标定（挪位后旧数全部作废）
3. **用一个写死的脚本策略（不学习）**跑 C6 收↔散循环，过一夜
4. 数人工干预次数，算 MTBH
5. **MTBH < 8 h → 回去修物理布置，不要去修算法**
6. **只有过了这道门槛，才打开学习循环**

第 3 步很便宜（一个脚本 + 一晚）却是决定性的。
**在 MTBH 门槛通过之前打开学习循环，等于用一个昂贵的随机搜索去掩盖一个物理布置问题。**
