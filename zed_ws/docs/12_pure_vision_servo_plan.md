## 0. 一句话

**不再把像素换算成 base_link 坐标。** 改成量「夹垫像素」和「积木像素」的差，
用「转一点关节 → 看像素动多少」现场测出来的增益把差消掉，一步一对账。

几何链需要三个串联常量都对：相机外参、桌高、工具模型。纯视觉链需要 **零个** ——
它们全被那个现场测的增益矩阵吸收掉了。增益不需要准，只需要**符号对、量级对**，因为它迭代。

## 1. 为什么换（不是偏好，是账面）

几何链的形状一直是：

```
像素 →（相机外参）→ base_link xyz →（桌高）→ 目标位姿
     → IK →（工具模型 TCP_TO_TIP）→ 关节指令 → 开环执行
```

三个常量串联，每一个都在历史上错过 50~200mm：

| 常量 | 历史错法 | 现状 |
|---|---|---|
| 桌高 `TABLE_TOP` | 0.7415 → 0.8108 → **0.790**，改了三次 | 权威值，但依赖一条摇操真值样本 |
| 工具模型 `TCP_TO_TIP` | 48.5mm → **168mm**（错了 3.5 倍） | 08-14 定案 |
| 相机外参 | `correction.json` 自己就是 +228.5px 的误差源（已盖 VOID） | 🔴 **仍有 ~100mm 世界系残差，未定位** |

第三行是关键：**几何链今天仍然是坏的，坏了大约 100mm，而且没人知道坏在哪。**
（STATUS 08-14：「还剩一个独立的 ~100mm 世界系误差，大概率相机外参」。）

要修它就得再做一次手眼标定 —— 那是烧掉过整整两天、并且产出过一个**反号**结果的工序。
纯视觉路线不修它，**绕过它**：不问「积木在哪」，只问「夹垫离积木还差几个像素、往哪个方向」。

## 2. 两件已经在仓库里的礼物

这条路线之所以是**最短**的，不是因为它聪明，是因为它要的两个零件都已经被造出来了 —— 都是当初当 bug 造的。

### 2.1 图像 Jacobian 已经被手工测过一列

STATUS 08-14「结构问题的判据不经过相机」那一节：只转 `arm_6` −30°，
**夹垫在像素里走 252.2px，tcp 走 140.7px（比值 1.79）**。

那次是拿它**诊断**工具模型的（比值不等于 1.0 ⇒ 偏移刚性挂在腕上 ⇒ `TIP_CENTER` 错）。
同一个测量换个用途就是**控制器**：一个关节的像素灵敏度。测三个关节就是 3×3 增益矩阵。
代码在 `scripts/pad_offset.py::swing()`，已经能跑。

### 2.2 夹垫检测已经稳到成了麻烦

`grasp_block.perceive()` 一直把**两片橙色夹垫**当积木候选检出来，稳定到：

- 相距 53.1~53.3mm（桌上真积木彼此都 >100mm），两次观测一致
- 闭合后两个 blob 合成一个（所以伺服期间夹爪必须**张开**，才有两个 blob 给你算中点）
- `_pad_px()` + `PAD_SEP_MM=(35,95)` 闸门都写好了

**几何链里它是假阳性，视觉链里它是基准。** 不用写新检测器，把自过滤的符号翻过来即可。

## 3. 三路相机 = 接力，不是融合

融合需要相机之间的外参 —— 那又是一次标定，正是要删的东西。所以设计成**接力**，
交接判据是「**目标出现在下一台相机的画面里**」，不是「把坐标转过去」。全程不算任何相机间变换。

| 段 | 相机 | 有效距离（实测） | 干什么 | 交给下一段的判据 |
|---|---|---|---|---|
| **A 粗** | ZED 2i（头） | 0.54~2.34m | 有没有积木、大致在哪、把手引到积木上方 ~30cm | 积木出现在腕部相机画面里 |
| **B 中** | D455（腕） | ≥295mm，`<250mm` 零像素 | 30cm → 10cm 收敛 | 积木出现在 D405 画面里 |
| **C 末** | **D405（腕）** | min-Z ~70mm | **STATUS 判定「必然开环」的最后 25cm** | 夹垫像素夹住积木 ⇒ close |

### 3.1 D405 是这三台里唯一不可替代的

STATUS 08-13 已经把这件事写死了：D455 对齐深度 **`<250mm` 一个像素都没有**、最近 295mm，
「合拢那 25cm 必然开环，**该用 D405**」。也就是说 **D405 补的正好是历史上唯一没有任何传感器
覆盖过的那一段** —— 而 `effort` 全是 `.nan`，接触力也摸不到，那 25cm 过去是纯赌。

### 3.2 D455 大概率是多余的，别为它卡住

ZED 能把手引到 ~30cm，D405 的 FOV 很宽（87°×58°）、min-Z 70mm，
**A 段的终点很可能已经落在 C 段的视野内**。那 B 段就不需要存在。

判据：A 段结束时拍一张 D405，积木在不在画面里。在 ⇒ **不接 D455**，两段就够。
先按「ZED + D405 两段」建，只有交接出现视野空洞才补 B 段。

### 3.3 腕部相机让伺服退化成更简单的形式

腕部相机和夹垫是**刚性同体**的 ⇒ 夹垫在腕部画面里的位置是**常量**。
所以 C 段的误差不是「两个动目标的差」，而是「积木质心 vs 一个固定准心」——
就是代码里已有的 `off_aim` / `wrist_track` 概念。准心测一次即可（拍一帧看夹垫在哪）。

ZED（头部固定，夹垫在画面里会动）才需要两个目标都测。

## 5. 唯一要写的东西：`scripts/servo.py`，两个命令

### 5.1 `servo.py measure --cam {zed,d405,d455}` — 现场测增益

摆到当前位姿附近，依次给 3 个关节各 ±小角度（用 `pad_offset.swing()` 那套），
每次拍一帧、量信号，得到 3×3 矩阵 `J`：

```
信号向量 s = [u_block, v_block, depth_at_block]     # 像素 u,v + 该点深度（D405 才有效到近距）
控制向量 q = [三个关节角]
J = Δs / Δq        （数值差分，每关节两个方向取平均）
```

- **只在当前位姿家族附近成立**，换个位姿重测 —— 6 个小动作，几十秒，比标定便宜三个数量级。
- 差分自动消掉任何**常量**外参误差（08-14 那次 `--swing` 就是靠这个立论的）。
- 落盘 `experiments/servo/J_<cam>_<pose>.json`，附证据帧 id。

### 5.2 `servo.py step --cam ... [--go]` — 一次迭代 = 一个 VISTA 动作

```
1. observe（走 vista_observe，帧进视觉记忆）
2. 检出夹垫（_pad_px）+ 积木；算误差 e = s_target − s_now
        · 腕部相机：s_target = 固定准心（夹垫像素，测一次）
        · ZED：     s_target = 两片夹垫的像素中点
3. Δq = 0.5 · J⁻¹ · e                        # 阻尼 0.5，不要一步吃掉
4. 🔴 过安全层：grasp_block.plan_path 碰撞 + path_floor_check 指尖地板
   —— 伺服只有提议权，否决权在原有闸门（见 §7）
5. 执行 → 重新 observe → 打印 预测Δpx vs 实际Δpx
6. 收敛判据 |e_px| < 阈值 且 depth 落在夹持带 ⇒ 建议 close
```

**停机判据（必须有，否则会磨）**：连续 3 步 `|e|` 降幅 <10% ⇒ 停下报告，不继续。
超时写在循环**内部**（memory `xr1-timeout-is-not-a-bound`：`timeout N python3` 拦不住 rclpy）。

自检：`servo.py --demo` —— 用盘上已有的历史帧离线跑一遍检测+解算，断言
①`_pad_px` 在已知帧上检出 2 个 blob 且间距落在 `PAD_SEP_MM`；②`J⁻¹·J ≈ I`；
③`e=0` 时 `Δq=0`；④安全层被调用过。不动机器人、秒级。

## 7. 纯视觉的边界：**只管瞄准，不管安全**

这条必须写死，否则会被误读成「删掉所有几何」：

| 管什么 | 用什么 | 纯视觉动它吗 |
|---|---|---|
| **瞄准**（去哪） | 像素误差 + 现场增益 | ✅ 全换 |
| **安全**（能不能去） | `grasp_block` 的 IK / `collide()` / `path_floor_check` / `TABLE_TOP=0.790` / `MIN_TIP_CLEAR=8mm` | ❌ **一个都不动** |

碰撞检查必须知道桌子在哪，所以 `TABLE_TOP` 留着。它估高只会拒动（保守方向）。
放宽任何闸门要人授权 —— 同 PITFALLS §55 那条禁令。

伺服 = **提议**；闸门 = **否决**。提议被否 ⇒ 报告，不是绕过。

## 11. 搭积木为什么比抓取更适合纯视觉

「把 A 放到 B 上」在几何链里要知道**两块**积木的世界坐标（两次外参误差）。
在像素里它是**一个对齐任务**：把 A 的像素质心开到 B 的像素质心上方，深度对上就松手。
两块积木在同一帧里 ⇒ 共同的相机误差直接约掉。

所以 P5 不是 P4 的加难，是同一个 `servo.py step` 换一个目标信号。
